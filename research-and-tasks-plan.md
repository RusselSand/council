# Исследование на весь совет и этап «Задачи»

План переделки, которую Валерия решила 15.10.2026, и как она сделана. Сюда дописывается по ходу
работы: что сделано в каждой части и где пришлось выбирать по месту.

## Зачем

Задачи режутся по одному итогу, и модель видит только свой итог. Поэтому задачи пересекаются:
одна делает работу соседней или обещает «X остаётся как есть», когда соседняя X убирает. Ни
один шаг этого не ловит: проверка пробелов сверяет только вопросы, а судья зависимостей —
только порядок.

## Решения

- План цельный важнее, чем «итог режется по одному». Задачи строятся одним планом на весь
  совет: участники видят все итоги всех потоков сразу.
- У задачи по-прежнему ровно один итог.
- Нарезчик не задаёт вопросов: нет пробелов задач, нет перенарезки, нет проверки пробелов.
  Что осталось неясным в реализации — в задаче раздел «Открытые вопросы», без решения.
- Задачи режут один раз, когда готовы: только когда во всех потоках итоги утверждены. Утвердить
  итоги можно, только если ни один итог не держит открытый вопрос или пробел.
- Любая правка в любом потоке после нарезки сбрасывает этап «Задачи» целиком.
- План — на весь совет, а не на поток.
- Поток выгружает заметки сразу после утверждения итогов, до задач: так следующий поток видит
  его решения и итоги через «решения проекта».
- Связь задач с итогами — односторонняя: в файле задачи есть её итог, в заметке итога строк
  задач нет. Следствие: след решений в коде (`project.py`, `found_in_code`) идёт от номера задачи
  к заметке итога по её строкам `- ISS-…`, поэтому для новых итогов он ничего не найдёт; для
  старых заметок со строками задач работает как раньше. Код следа не трогаем.
- Участники сразу пишут план последовательно, с зависимостями. Отдельного судьи зависимостей нет.
- Утверждение идей переезжает в этап «Группы» — по группе.
- Репозиторий и дизайн — один этап «Исследование» на весь совет, между «Группами» и
  «Потоками». Одна карта кода и одно описание макета, которыми пользуются все потоки и этап
  «Задачи».
- Порядок потоков совет не навязывает: поток B видит решения A, только если A уже выгружен.
- Сохранить нужно только совет `7c1720bc`; его переносят разовым скриптом, который в
  репозиторий не попадает.

## Этапы совета

1. Бриф — как сейчас.
2. Нарезка — как сейчас.
3. Группы — как сейчас, плюс утверждение идеи каждой группы.
4. Исследование — репозиторий и макет на весь совет; обе части можно пропустить.
5. Потоки — решения проекта, вопросы, варианты, решения, итоги, выгрузка заметок.
6. Задачи — план работ на весь совет и выгрузка файлов задач.

## Части работы

1. Выгрузка заметок без задач: поток выгружает вопросы, варианты, ADR и итоги после
   утверждения итогов; строк задач в итогах и файлов задач в выгрузке потока больше нет.
2. Идеи — в «Группы», репозиторий и дизайн — в этап «Исследование».
3. Этап «Задачи»: план на весь совет, раздел «Открытые вопросы», сброс при правке потока,
   выгрузка файлов задач. Нарезка в потоке, перенос задач, пробелы задач, перенарезка, проверка
   пробелов и судья зависимостей уходят.
4. Перенос `7c1720bc` — отдельно, вне репозитория.

## Как сделано

Дописывается по частям.

### Часть 1. Выгрузка заметок без задач

- Утверждение итогов теперь записано в самих итогах: `OutcomeDiscovery.approved`. Собрали итоги
  заново — новая сборка не утверждена. Раньше утверждение узнавали по тому, что задачи уже
  режутся.
- Черновик и выгрузка потока держатся за утверждённые итоги (`NotesDraft.outcomes`,
  `NotesExport.outcomes` — номер сборки итогов), а не за нарезку задач. Поля `issues`,
  `issues_root` и `numbers` из них ушли.
- В заметке итога нет строк задач. Номера задач и файлы задач поток больше не раздаёт и не
  пишет: `numbered_issues`, `issue_parts`, `held_issues`, `issue_text` из `export.py` убраны —
  в части 3 их заменит выгрузка этапа «Задачи». `issue_files.py` (чтение и запись файлов задач)
  остался.
- Файлы задач из прежней выгрузки потока (`type: issue`) больше не считаются его: черновик их не
  переписывает и не предлагает удалить.
- Шаг «Документация» открывается сразу после утверждения итогов, не дожидаясь нарезки. Нарезка
  внутри потока пока осталась как была — её уберёт часть 3.
- Тесты, которые проверяли номера и файлы задач в выгрузке потока, убраны; похожие появятся
  в части 3 для этапа «Задачи».
- Мимоходом: два теста в `test_pipeline.py`
  (`test_another_snapshot_is_a_new_call_not_a_free_retry` и соседний) иногда падают при общем
  прогоне и проходят по отдельности — это было и до правок, на `main`.
