# Project Decisions: правки к промптам

Промпты `project_decisions_discovery.md` и `project_decisions_judge.md`. Формат «было →
стало», цитаты дословные. В конце — что из этого делает код, а не промпт.

Главное, чего не хватает: в промптах нет следа из коммитов, хотя мы договорились, что это
первая часть поиска. Остальное — уточнения.

---

## 1. След из коммитов (главное)

Код до вызова моделей проходит `git log` по файлам из карты репозитория, находит в коммитах
`ISS-x`, по заметкам — их OUTCOME и ADR. Такие ADR в каталоге помечены: каким коммитом, в
каком файле, через какую задачу и итог. Модели нужно сказать, что это значит.

**Было** (discovery, «Тебе даны»):
> - каталог ранее принятых ADR в сокращённом формате: ID, OPEN QUESTION, принятое решение.

**Стало:**
> - каталог ранее принятых ADR в сокращённом формате: ID, IDEA, к которой относится решение,
>   OPEN QUESTION, принятое решение, статус; у части ADR — след в коде (`found_in_code`):
>   коммит с номером задачи, которая реализовала итог этого решения, в файле, который новая
>   IDEA, по карте репозитория, будет затрагивать.

**Было** (discovery, «Критерии отбора», после пункта 5):
> 5. Может потребовать пересмотра при реализации IDEA.

**Стало:**
> 5. Может потребовать пересмотра при реализации IDEA.
>
> След в коде (`found_in_code`) — сильный довод: IDEA будет менять код, сделанный под это
> решение. Но не автоматическое включение: файл могли менять по другой задаче, не связанной
> с IDEA. Проверь, касается ли само решение того, что меняет IDEA. Отсутствие следа не
> говорит против ADR: код мог быть написан до того, как номера задач стали писать в коммиты,
> а решение может и вовсе не касаться кода.

**Стало** (discovery, «Оценка», новый пункт после первого):
> - Есть ли у ADR след в коде, и подтверждает ли он связь с IDEA?

**Было** (judge, «1. Проверка кандидатов»):
> - достаточно ли сведений для определения релевантности.

**Стало:**
> - достаточно ли сведений для определения релевантности;
> - есть ли у ADR след в коде (`found_in_code`) и подтверждает ли он связь с IDEA — сильный
>   довод, но не автоматическое включение.

**Стало** (в обоих, перед `## IDEA` — как выглядит запись каталога, чтобы модели знали поля):

```json
{
  "adr_id": "ADR-0007",
  "idea": "Платежи принимаются без ручной сверки.",
  "question": "Через какого провайдера идут платежи?",
  "decision": "Платежи идут через Stripe.",
  "status": "active",
  "found_in_code": [
    {"issue": "ISS-0012", "outcome": "OUT-0004", "commit": "a1b2c3d",
     "file": "billing/api.py"}
  ]
}
```

## 2. К какой идее относится решение

Решение без своей идеи читается двусмысленно: «Храним в файлах» — что храним? Идея — одно
предложение, в токенах дёшево, а точность отбора заметно выше. Уже учтено в п. 1 (поле
`idea`); в текст промпта добавить ничего не нужно, кроме «Тебе даны».

---

## 3. Пересмотренные решения

Решение могли пересмотреть в другом совете: в графе из ADR растёт вопрос, а на него —
новый ADR. Код пометит это в каталоге статусом:
- `active` — действует;
- `under_review` — по нему открыт вопрос, нового решения ещё нет;
- `superseded` — заменено другим ADR (номер — в `superseded_by`).

**Стало** (discovery и judge, после «Существующие ADR являются контекстом проекта…» / в
«1. Проверка кандидатов»):
> Учитывай статус ADR:
> - `superseded` не отбирай — отбери заменившее его решение, если оно относится к IDEA;
> - `under_review` отбирай только как `potential_conflict` или `uncertain`: решение под
>   вопросом.

---

## 4. Судья: только кандидаты агентов?

Сейчас неясно, может ли судья добавить ADR из каталога, которого не предложил ни один
агент: «Собери уникальные ADR ID из результатов» — и при этом «ADR, предложенный только
одним агентом, может быть включён…». Предлагаю явно ограничить кандидатами: судья проверяет,
а не ищет заново, — дешевле и предсказуемее.

**Было** (judge):
> Собери уникальные ADR ID из результатов независимых агентов.

**Стало:**
> Собери уникальные ADR ID из результатов независимых агентов. Проверяй только их: ADR,
> которого не предложил ни один агент, не добавляй.

Если хочешь, чтобы судья мог добавить пропущенное, — скажи, тогда наоборот: «можешь
добавить ADR из каталога, если его связь с IDEA очевидна, и укажи это в reason».

---

## 5. Язык и формулировки

Ничего не меняю сейчас: при переводе промптов на английский добавятся общие строки — `reason`
на языке работы (`{{language}}`) и простыми словами.

---

## Что делает код, а не промпт

- **Каталог пуст** (заметок ещё нет) — шаг не зовёт моделей вовсе, блок пишет «прошлых
  решений нет».
- **Участники вернули одинаковые списки** — судья не нужен, как на шаге «Вопросы».
- **След в коде** собирает код: `git log` по файлам из карты, номера `ISS-x` по регулярке,
  связи по заметкам. Мелкий клон или коммиты без номеров — след пустой, остаётся поиск по
  смыслу.
- **Решения соседних потоков** попадают в каталог, только когда поток выгружен; блок
  предупреждает, какие потоки не выгружены.
- Отобранное человек подтверждает галочками; в промпты вопросов, вариантов и решений идут
  только отмеченные — с категорией (`applicable`, `potential_conflict`, `uncertain`) и
  причиной.
